## 1. 物理与几何语义（M2.1 `bamer_mouse/kinematics.py`）

| 项 | 契约内容 | 来源 |
| --- | --- | --- |
| 单位 | 全仿真以"格"为单位，格边长 `CELL = 1.0`，无量纲；mm 仅展示层可选标注（1 格 ≡ 180 mm），不进入仿真核心 | D3 已定 |
| 世界系 | x 向右 0~n-1，y 向上 0~n-1，起点 (0,0) 在左下角；墙体为零厚度线段，位于格边界 | 与 bamer_env 一致 |
| 位姿 | `Pose(x, y, theta_deg)`；静止规范位姿 = 格中心 (x+0.5, y+0.5)；朝向世界系角度：东 0° / 北 90° / 西 180° / 南 270° | M2.1 |
| 动作原语 | `{F 前进一格, TL 左转90°, TR 右转90°, TB 后转180°}`，与 BamerEnv 占位动作空间同序 (0/1/2/3) | D5 默认项 |
| 碰撞语义 | 仅 F 可碰撞：动作指向有墙边界 = 位置不变 + 计 1 步 + `Collision` 事件；无物理滑移。**惩罚/终止语义随 §6 用户奖励设计定** | 占位（待确认） |
| 计步 | 每个动作恰计 1 step（含旋转与碰撞）；旋转计入步数（R4） | 题目铁律 |
| 逻辑格 | 动作完成后逻辑格 = floor(位姿)；规范位姿下即所在格 | M2.1 |
| 插值 | 匀速插值仅用于动画呈现（t∈[0,1]，F 平移 / 转向原地旋转）；插值位姿为非规范位姿，**不得**用于传感器扫描与逻辑判定 | M2.1 |

## 2. 传感器契约（M2.2 `bamer_mouse/lidar.py`，D4 默认项——可推翻）

| 项 | 默认值 | 说明 |
| --- | --- | --- |
| FOV / 束数 | 360° / 180 束（2°/束） | 训练时降束提速与否由用户定 |
| 量程 | 2.0 格 | 开口后下一堵墙 ≥1.5 格，量程内可见豁口 |
| 噪声 | 关闭；开启时 σ_range=0.02 格（仅作用回波距离，截断于量程内） | 独立随机流（default_rng），由 reset 种子派生 → 同种子含噪逐位可复现 |
| 安装位置 | 鼠体中心（格中心规范位姿） | 扫描时机 = 每 step 末尾 + reset 第 0 帧 |
| 束角约定 | 机体系角度，0°=正前方、逆时针为正；束 i 角 = -180° + 2i° | 束 0 正后方；与朝向/world 角换算 = pose.theta + 束角 |
| 无回波 | `ranges[i] = NaN`；世界系点云 `info["points"]` 与束一一对应 `(n,2)`，NaN 行=无回波 | **"丢弃 vs NaN 对齐"本实现选 NaN 对齐（利于 RL 定长/存档），原 PLAN 注"默认丢弃"——随本契约定稿确认** |
| raycast | DDA 格边界穿越（Amanatides & Woo），角点 tie 先竖直后水平；开口 = 缺失墙边界，射线自然穿过 | 单测解析解对拍通过（含噪声模式） |
| 信息封闭 | 雷达输出（ranges/angles/points）是算法侧唯一环境信息通道之一；wall_query 回调由环境侧注入，`bamer_mouse` 不 import `bamer_env` | R1 |
| 占据栅格 | `occupancy_grid` 只依赖量测 + 自身位姿复算（无墙查询）；与墙查询参考实现逐格等价（单测实证） | R1 自洽 |

## 3. 事件语义（M1.1 `bamer_env/interaction.py`）

| 事件 | 触发 | payload 关键字段 |
| --- | --- | --- |
| `Reported` | 每步实时上报自身格坐标（题目规则） | x, y |
| `ImageFeed` | 进入状态机所在格（停留不重复，离开再进重新下发） | machine, label, image, first |
| `Pickup` | **【已实现 2026-11-20】** 进入状态机所在格且空手且未送达 → carrying 生效（首达即识别+拾取同步；识别时手持他机仅识别、事后 Pick 回取；已送达不重复拾取；单机负载） | machine, x, y |
| `DestinationFeed` | **【已实现 2026-11-20】** 进入终点所在格（发现终点；终点位置封闭，须自主发现；first 标记首次，与 Arrived 可同入并存） | destination, image, first |
| `Arrived` | **已携带**状态机映射的终点格到达（派送自动完成；未携带时进终点格仅触发 `DestinationFeed`） | machine, destination, x, y |
| `Collision` | F 指向有墙边界 | x, y, direction |
| `TaskComplete` | 全部派送达成（仅转变时一次） | steps |
| `Timeout` | 达到 max_steps（truncated） | max_steps |

**两项语义已确认（2026-11-20 用户拍板）+ 一项实现期推导语义（随冻结确认）**：

1. **派送触发**：进入"**已携带**且已识别"状态机映射的终点格 → 自动完成派送（`Arrived`）；未携带时进终点格 = 仅发现该终点（`DestinationFeed`）。终点位置固定 (8,8)/(7,7) 但对机器鼠封闭，须自主发现。
2. **ImageFeed 载荷可见性（R1）**：算法侧合法字段仅 `image`（像素）+ 事件步号；`machine`/`label` 仅供环境侧评估与展示（`CameraUnit` 已按此实现：识别流水线只消费像素，GT 仅评估口径参与）。poi 通道"已识别"标记的数据来源 = 分类器输出，非事件字段。
3. **Pickup 首达语义（实现期推导，见 CHANGELOG 2026-11-20）**：执行器只产出 D5 原语（§5），env 层不感知 option 意图 → 拾取触发 = "进入状态机格且空手且未送达"；首达即 ImageFeed+Pickup 同步（否则一切首次拾取需二次到访，与 R3 步数最优矛盾）；"识别时手持他机 → 事后 Pick 回取"保持 Pick 选项真实语义。

## 4. 观测空间——D7 定稿参数（2026-11-20 填写，依据 rl_algorithm_design.md §2）

算法侧输入 = **16 通道全图信念张量 (16, 16, 16) uint8**（由算法侧账本派生）：

| 参数 | 定稿值 |
| --- | --- |
| 范围 | **全图 16×16 信念**（局部 7×7 窗口方案否决——全图信念才是探索决策的充分统计量） |
| 对齐 | `world`（世界对齐，x 右 y 上，与 maze.py 坐标约定一致） |
| 通道 | 4 墙位(N/E/S/W, 0=unknown 1=free 2=blocked) + 4 位姿(位置⊗朝向 one-hot) + 2 机器(0/1/2) + 2 终点(0/1) + 2 carrying(全图广播) + 2 轨迹(trail_prev_option / pose_prev_boundary) |
| 多帧堆叠 | 无堆叠——时序上下文由轨迹通道承担（GRU 为预留升级开关） |
| 数值编码 | uint8 小整数类别编码；喂网络时转 float 归一化随网络实现定 |
| obs 装载方式 | **算法侧组袋**：obs 维持占位 Dict（cell/heading/identified/delivered），量测与事件经 info 透传；探测账本 + 轨迹账本与信念派生在 `algo/belief.py`（账本属智能体记忆归算法侧，R1 自检面最小） |

## 5. 动作空间——D6 定稿（2026-11-20 填写，依据 rl_algorithm_design.md §3）

物理层 = D5 原语 {F, TL, TR, TB}（每动作计 1 步，不变）。决策层 = **选项 C 分层**（SMDP/options：高层仅在 option 边界决策，v1 commit-until-done 不做中途打断）：

| 高层动作 | 参数 | 合法条件（掩码） | 终止 |
| --- | --- | --- | --- |
| `Explore` | 目标点 (x,y)（256 格逐格打分） | 目标格已知空闲且从当前 (格,朝向) 在信念图上可达 | 到达目标；目标不可达 → 中止，失败信号交还高层 |
| `Pick` | 状态机标签（2 选 1） | 该机已识别 **且** 空手（单机负载已确认） | 到达该机格 → `Pickup`，carrying 生效 |
| `Deliver` | 无参数（目标 = `delivery_map[手中机器]`，硬编码执行器） | 持机 **且** 对应终点已定位 | 到达终点格 → `Arrived` 自动派送 |

合法选项 = 256+2+1 = **259**；非法动作由网络侧掩码（Q 置 −∞ 且不进 dueling 均值）。执行器 = (格,朝向) 16×16×4 = 1024 态 BFS（转向计步）+ 每步重规划。

## 6. 奖励接口——D8 定稿（2026-11-20 填写，依据 rl_algorithm_design.md §5）

| 信号 | 数值 | 触发 |
| --- | --- | --- |
| 步代价 | **−1 / 步**（每个低层动作，含旋转与碰撞） | 每步 |
| 首次识别 | **+100** / 台（首次 `ImageFeed`） | 探索里程碑 |
| 终点发现 | **+100** / 个（首次发现并识别终点，`DestinationFeed`） | 探索里程碑 |
| 送达 | **+300** / 台（首次 `Arrived`） | 派送里程碑 |
| 碰撞 | **无额外惩罚**（已确认 2026-11-20：模型一般不会撞墙，时间代价即惩罚） | `Collision` |
| 超时 | **无额外惩罚**（已确认 2026-11-20；truncated 截断即可） | `Timeout` |

SMDP 折算：option 累计奖励 = Σ(−1) + 途中里程碑，高层转移按 γ^τ 折扣。奖励实现于算法侧包装层/Env 钩子，事件来源 `info["events"]`。

## 7. 数据格式（M2.4 `bamer_mouse/dataio.py`，已实现）

- `EpisodeRecord`：meta（迷宫 sha256 哈希、reset 种子、场景配置、雷达参数、时间）+ 逐步（step、位姿、动作、ranges/angles、世界系点云、事件）；
- 存储：`<基名>.npz`（数值数组，NaN=无效）+ `<基名>.json`（meta + 事件）；目录 `data/episodes/`；
- 格式中立（npz/JSON，MATLAB 可直读），往返一致性单测通过。
